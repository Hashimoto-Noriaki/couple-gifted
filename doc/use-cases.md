# ユースケース

- **最終更新**：2026-07-30
- **前提ドキュメント**：`docs/requirements.md`、`docs/user-stories.md`
- **本書の目的**：ユーザーストーリーを操作レベルに分解し、正常系と異常系を確定させる。**request spec の一覧と1対1で対応させる**

---

## ユースケースとは

**ユーザーがシステムとどうやり取りするか**を具体的な操作レベルで記述したもの。

### ユーザーストーリーとの違い

| | ユーザーストーリー | ユースケース |
| --- | --- | --- |
| 視点 | なぜ・何をしたいか | どうシステムと対話するか |
| 粒度 | 大きい（目的レベル） | 小さい（操作レベル） |
| タイミング | 先に書く | ユーザーストーリーの後に書く |
| 例 | カップルメンバーとして、サプライズを準備したい | ①スポット詳細を開く ②保存ボタンを押す ③「サプライズ」を選ぶ ④保存される |

### 型

```bash
ユースケース名：〇〇する
アクター：会員 / 管理者
事前条件：〇〇であること
基本フロー（正常系）：
  1. 〇〇する
例外フロー（異常系）：
  - 〇〇の場合：△△する
事後条件：〇〇の状態になっている
```

### 本プロジェクトでの例外フローの扱い

例外フローは「エラー画面の文言集」ではなく、**設計上の判断を確定させる場**として使う。

本サービスでは、例外の多くが技術的な失敗ではなく**関係の状態変化**によって起きる。

- 招待コードを渡した後で、発行者が別の相手と連携してしまった
- サプライズで保存したスポットが、すでに共有保存リストに入っていた
- 記録を書いた後で関係ステージが変わった
- カップル連携中の会員が退会した

これらは正常系の延長では発見できない。**例外フローを書くことが、要件の穴を見つける手段になっている。**

## STEP1. ユースケースの抽出

### 認証・アカウント

**US**：ゲストとして、新規登録したい

```bash
ユースケース名：新規登録する
アクター：ゲスト
事前条件：アカウントが存在しないこと
基本フロー：
  1. メールアドレスを入力する
  2. パスワードを入力する
  3. 利用規約・プライバシーポリシーへの同意にチェックを入れる
  4. 登録ボタンを押す
  5. 確認メールが送信される
  6. トップページに遷移する
例外フロー：
  - メールアドレスが既に登録済みの場合：「このメールアドレスは既に使われています」を表示する
  - パスワードが要件を満たさない場合：満たすべき条件を表示する
  - 規約への同意がない場合：登録ボタンを非活性にする
  - 停止済みアカウントと同じメールアドレスの場合：登録済みと同じ扱いにする（停止の事実を伝えない）
事後条件：会員（ソロ）としてログイン状態になっている
```

```bash
ユースケース名：ログインする
アクター：ゲスト
事前条件：アカウントが登録済みであること
基本フロー：
  1. メールアドレスを入力する
  2. パスワードを入力する
  3. ログインボタンを押す
  4. トップページに遷移する
例外フロー：
  - メールアドレスまたはパスワードが誤っている場合：どちらが誤っているかを区別せずに表示する
  - 連続して失敗した場合：一時的に試行を制限し、再試行できる時刻を表示する
  - アカウントが停止されている場合：停止されていることと問い合わせ先を表示する
事後条件：ログイン状態になっている
```

```bash
ユースケース名：ログアウトする
アクター：会員（ソロ）・カップルメンバー・管理者
事前条件：ログイン状態であること
基本フロー：
  1. ログアウトボタンを押す
  2. トップページに遷移する
例外フロー：なし
事後条件：ゲスト状態になっている
```

```bash
ユースケース名：退会する ※未決事項あり
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. 設定画面から退会を選ぶ
  2. 自分が書いたレビューの扱いを選択する
  3. 退会後に復旧できないことの確認に同意する
  4. パスワードを再入力する
  5. 退会が完了する
例外フロー：
  - パートナーと連携中の場合：連携が解除されること、カップルレビューと共有保存リストがどうなるかを提示してから進む
  - パスワードが誤っている場合：エラーを表示し、退会処理を行わない
事後条件：ログインできない状態になっている。選択に応じてレビューが削除または匿名化されている
未決：退会時のレビュー・保存リストの扱い（要件定義書 未決事項 #2）
```

### プロフィール

**US**：会員として、自分に合った提案を受けたい

```bash
ユースケース名：プロフィールを編集する
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. プロフィール編集画面を開く
  2. ニックネーム・年代・居住エリア・好みのタグ・子どもの有無を入力する
  3. 保存ボタンを押す
  4. 「保存しました」と表示される
例外フロー：
  - 必須項目（ニックネーム）が未入力の場合：エラーを表示する
  - 文字数制限を超えた場合：上限を表示する
  - 好みのタグが上限数を超えた場合：上限を表示する
事後条件：プロフィールが更新されている。以降の検索・レコメンドの初期値に反映される
```

### カップル連携

**US**：会員として、招待コードを発行してパートナーを誘いたい

```bash
ユースケース名：招待コードを発行する
アクター：会員（ソロ）
事前条件：ログイン状態であること・パートナーと連携していないこと
基本フロー：
  1. カップル連携画面を開く
  2. 招待コードを発行するボタンを押す
  3. コードと有効期限（残り日数）が表示される
  4. コードをコピーして任意の手段で相手に渡す
例外フロー：
  - 既に有効なコードがある場合：新規発行せず、既存のコードと残り日数を表示する
  - 再発行を選んだ場合：それ以前のコードが無効になることを警告してから発行する
  - 発行のレート制限に達した場合：次に発行できる時刻を表示する
  - 既にパートナーと連携している場合：発行ボタンを表示しない
事後条件：有効な招待コードが1つだけ存在している
```

```bash
ユースケース名：招待コードを入力して連携する
アクター：会員（ソロ）
事前条件：ログイン状態であること・パートナーと連携していないこと
基本フロー：
  1. カップル連携画面を開く
  2. 受け取った招待コードを入力する
  3. 発行者のニックネームが表示され、連携するか確認される
  4. 連携するボタンを押す
  5. 「連携しました」と表示される
  6. 関係ステージの設定を促される
例外フロー：
  - コードが存在しない場合：「このコードは使用できません」を表示する
  - コードの有効期限が切れている場合：「このコードは使用できません」を表示する
  - コードが既に使用済みの場合：「このコードは使用できません」を表示する
  - 自分が発行したコードの場合：「このコードは使用できません」を表示する
  - 発行者が既に別の相手と連携している場合：「このコードは使用できません」を表示する
  - 発行者が退会済み・停止中の場合：「このコードは使用できません」を表示する
  - 入力者が既に別の相手と連携している場合：先に解除が必要であることを表示する
  - 連続して入力に失敗した場合：一時的に入力を制限し、再試行できる時刻を表示する
  - 二人が同時に同じコードを入力した場合：先に処理された1人だけが連携し、もう1人には使用済みと同じ応答を返す
事後条件：双方がカップルメンバーになっている。使用されたコードは無効になっている
補足：無効なコードの理由（存在しない／期限切れ／使用済み／発行者側の状態）を区別して表示しない。
      区別すると、コードの存在有無を外部から判定できてしまうため
```

```bash
ユースケース名：関係ステージを設定・更新する
アクター：カップルメンバー
事前条件：パートナーと連携していること
基本フロー：
  1. カップル設定画面を開く
  2. 交際開始日を入力する（結婚している場合は結婚日も入力する）
  3. 保存ボタンを押す
  4. 現在の関係ステージが自動で算出され、表示される
例外フロー：
  - 結婚日が交際開始日より前の場合：エラーを表示する
  - 未来の日付が入力された場合：エラーを表示する
  - 日付が未入力の場合：ステージを「未設定」とし、ステージ別の絞り込み結果に自分たちを含めない
  - パートナーが同時に別の値を保存した場合：後から保存された値を採用し、変更内容を双方に表示する
事後条件：カップルの関係ステージが更新されている。
        **過去に投稿した記録に紐づくステージは変更されない**
```

```bash
ユースケース名：連携を解除する ※未決事項あり
アクター：カップルメンバー
事前条件：パートナーと連携していること
基本フロー：
  1. カップル設定画面から連携解除を選ぶ
  2. カップルレビューと共有保存リストがどうなるかが提示される
  3. 解除は取り消せないことの確認に同意する
  4. 解除ボタンを押す
  5. 「解除しました」と表示される
例外フロー：
  - 相手が既に解除している場合：解除済みの状態を表示する
  - 相手が退会済みの場合：連携は自動的に解除された状態として扱う
事後条件：双方が会員（ソロ）に戻っている。
        自分のサプライズ保存リストは相手に見えない状態を維持している。
        同じ相手と再度連携できる
未決：連携解除後のカップルレビューと共有保存リストの帰属、相手への通知の有無（要件定義書 未決事項 #3）
```

### スポットを探す

**US**：会員として、条件に合う候補だけを見たい

```bash
ユースケース名：スポットを検索する
アクター：ゲスト・会員（ソロ）・カップルメンバー
事前条件：なし
基本フロー：
  1. 検索画面を開く
  2. エリア・カテゴリ・予算帯・シーンの条件を選ぶ
  3. 検索ボタンを押す
  4. 条件に合うスポットが一覧表示される
例外フロー：
  - 条件に合うスポットがない場合：見つからなかったことと、条件を緩める案を表示する
  - 条件が未指定の場合：居住エリアを初期値として補完する
  - カップルメンバーの場合：関係ステージと、子どもの有無から推定した子連れ訪問を初期値として補完し、補完したことを表示する
  - ゲストの場合：ステージによる絞り込みは選べるが、初期値の補完はしない
事後条件：検索結果が表示されている。条件は次回訪問時にも保持されている
```

```bash
ユースケース名：レビューを関係ステージで絞り込んで読む
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. スポット詳細画面を開く
  2. 「自分たちに近い条件で見る」を選ぶ
  3. 関係ステージ・予算帯・子連れ訪問が近いレビューだけが表示される
  4. 絞り込みを外して全件表示に切り替えられる
例外フロー：
  - 絞り込み後の件数が0件の場合：0件であることを示し、条件を緩めた結果を併せて提示する
  - 絞り込み後の件数が極端に少ない場合：件数を明示し、参考にする際の注意を添える
  - カップル未連携またはステージ未設定の場合：絞り込みを選べないことと、設定を促す案内を表示する
事後条件：絞り込み条件と件数が画面上に明示されている
補足：絞り込みは「投稿当時のステージ」を基準にする。投稿者の現在のステージではない
```

### 記録する

**US**：カップルメンバーとして、二人で行った体験として記録を残したい

```bash
ユースケース名：レビューを投稿する
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. スポット詳細画面から投稿画面を開く
  2. 評価（5段階）を選ぶ
  3. 予算帯（ふたり合計・税込）・シーン・子連れ訪問・パートナーの反応を選ぶ
  4. 本文を入力する
  5. 写真を添付する（任意）
  6. 投稿ボタンを押す
  7. レビューが公開され、スポットの評価サマリに反映される
例外フロー：
  - 評価が未選択の場合：投稿ボタンを非活性にする
  - 本文が文字数制限を超えた場合：上限を表示する
  - 写真のサイズ・形式が要件を満たさない場合：条件を表示する
  - 写真の枚数が上限を超えた場合：上限を表示する
  - カップル未連携の場合：カップル属性を持たない記録として保存し、ステージ別の集計に含めない
  - 関係ステージが未設定の場合：投稿は可能とし、ステージ別の集計に含めない旨を表示する
  - 投稿途中で離脱した場合：下書きとして保存する
  - 同一スポットに既に投稿がある場合：※未決（下記参照）
事後条件：レビューが公開されている。
        **投稿時点の関係ステージが記録に紐づいており、後から変更されない**。
        スポットの評価件数・平均評価が更新されている
未決：同一スポットへの複数回の投稿を許すか（訪問ごとに記録したい要求がある一方、
      平均評価が特定のカップルに偏る懸念がある）
```

```bash
ユースケース名：下書きを保存する
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. レビュー投稿画面で入力する
  2. 下書き保存ボタンを押す
  3. 「下書きを保存しました」と表示される
例外フロー：
  - 何も入力されていない場合：下書きを作成しない
事後条件：下書きが保存されている。**パートナーからは参照できない**
```

### 保存する

**US**：カップルメンバーとして、パートナーには絶対に見えない保存リストを作りたい

```bash
ユースケース名：スポットをサプライズで保存する
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. スポット詳細画面で保存ボタンを押す
  2. 「二人で共有」か「サプライズ（自分だけ）」を選ぶ
  3. 「サプライズ」を選ぶ
  4. 保存される
例外フロー：
  - 同じスポットが既に共有保存リストに入っている場合：
    そのスポットはすでにパートナーに見えている状態であることを伝え、
    サプライズにならない可能性を警告してから保存する
  - 同じスポットを既にサプライズで保存している場合：保存ボタンを保存済み表示に切り替える
  - 保存件数が上限を超えた場合：上限を表示する
事後条件：サプライズとして保存されている。
        パートナーのアカウントからは、一覧・詳細・検索結果・件数のいずれにも現れない。
        保存の存在自体もパートナーに伝わらない
```

```bash
ユースケース名：サプライズ保存を共有に変更する
アクター：カップルメンバー
事前条件：サプライズとして保存したスポットがあること
基本フロー：
  1. サプライズ保存リストを開く
  2. 対象のスポットで「共有に変更」を選ぶ
  3. 変更するとパートナーに見えるようになることが警告される
  4. 同意して変更する
例外フロー：
  - パートナーと連携していない場合：共有に変更できないことと、連携を促す案内を表示する
  - 同じスポットが既に共有保存リストにある場合：重複を作らず、サプライズ側の登録を削除する
事後条件：共有保存リストに移動している。パートナーから参照できる状態になっている
補足：共有からサプライズへの変更は、パートナーが既に見た可能性を消せないため、
      「サプライズに戻す」という表現は用いない
```

### 提案を受ける

**US**：カップルメンバーとして、いくつかの質問に答えるだけで提案を受けたい

```bash
ユースケース名：診断を受けてスポットの提案を受ける
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. 診断を開始する
  2. 質問に順番に回答する
  3. 回答に基づいてスポットが提案される
  4. 気になったスポットを保存できる
例外フロー：
  - 回答途中で離脱した場合：次回は途中から再開できる
  - 提案できるスポットがない場合：条件を緩めた提案を代わりに表示する
  - 提案理由が説明できない場合：提案しない（理由を示せない提案は行わない）
事後条件：提案結果が表示されている。回答内容は次回の初期値として保持されている
```

### 安全・運営

**US**：会員として、不適切な投稿を通報したい

```bash
ユースケース名：投稿を通報する
アクター：会員（ソロ）・カップルメンバー
事前条件：ログイン状態であること
基本フロー：
  1. 対象の投稿から通報を選ぶ
  2. 理由を選択する（任意で補足を入力する）
  3. 通報ボタンを押す
  4. 受け付けたことが表示される
例外フロー：
  - 自分の投稿の場合：通報の選択肢を表示しない
  - 同じ投稿を既に通報している場合：受け付けたことのみを表示し、重複した通報を作成しない
事後条件：通報が管理者の未対応一覧に追加されている。
        通報したことは投稿者に伝わらない
```

```bash
ユースケース名：通報に対応する
アクター：管理者
事前条件：管理者としてログイン状態であること
基本フロー：
  1. 管理画面の通報一覧を開く
  2. 通報内容と対象の投稿を確認する
  3. 対応（対応不要 / 投稿削除 / ユーザー停止）を選ぶ
  4. 対応理由を入力する
  5. 確認ダイアログで実行する
例外フロー：
  - 他の管理者が既に対応済みの場合：対応済みであることと、対応者・対応内容を表示する
  - 対象の投稿が既に削除されている場合：通報を対応済みとして閉じる
  - 対応理由が未入力の場合：実行できないようにする
事後条件：通報が対応済みになっている。
        実行者・日時・対応内容・理由が記録されている
```

```bash
ユースケース名：スポットを登録・編集する
アクター：管理者
事前条件：管理者としてログイン状態であること
基本フロー：
  1. 管理画面のスポット一覧を開く
  2. 新規登録または編集を選ぶ
  3. 名称・カテゴリ・エリア・位置情報などを入力する
  4. 保存する
例外フロー：
  - 同名・同一位置のスポットが既に存在する場合：重複の可能性を警告し、統合するか別で登録するかを選ばせる
  - 位置情報が取得できない場合：エリアのみで登録できるようにする
  - レビューが投稿済みのスポットを削除しようとした場合：削除せず、非掲載に切り替える
事後条件：スポットが検索対象に反映されている
```
